# Feature Specification: 用户认证与可视化仪表盘

**Feature Branch**: `002-user-auth-dashboard`  
**Created**: 2025-11-25  
**Status**: Draft  
**Input**: 用户需求：增加用户认证、代码安全、首页仪表盘、UI优化

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用户注册与登录 (Priority: P1)

作为一名新用户，我希望能够通过注册账号并登录，以便将我的技能数据安全地存储在云端，并在多设备间同步。

**Why this priority**: 用户认证是多设备同步和数据安全的基础。

**Independent Test**: 可以通过访问登录页、填写注册表单、登录验证、退出登录来完整测试。

**Acceptance Scenarios**:

1. **Given** 用户首次访问应用, **When** 用户点击"注册"按钮, **Then** 显示注册表单（用户名、邮箱、密码、确认密码）
2. **Given** 用户填写注册表单, **When** 用户提交且密码符合强度要求（至少8位、包含大小写字母和数字）, **Then** 注册成功并自动登录
3. **Given** 已注册用户访问应用, **When** 用户输入正确的用户名和密码, **Then** 登录成功并跳转到首页仪表盘
4. **Given** 用户已登录, **When** 用户点击"退出登录", **Then** 清除登录状态并返回登录页
5. **Given** 用户输入错误密码, **When** 用户点击登录, **Then** 显示友好的错误提示（"用户名或密码错误"）

---

### User Story 2 - 代码安全防护 (Priority: P1)

作为系统管理员，我希望应用具备基础的安全防护措施，以便保护用户数据不被恶意攻击。

**Why this priority**: 安全是应用的基石，必须在早期实现。

**Independent Test**: 可以通过尝试XSS注入、SQL注入、CSRF攻击来验证防护措施。

**Acceptance Scenarios**:

1. **Given** 用户在日志中输入 `<script>alert('XSS')</script>`, **When** 日志显示时, **Then** 脚本被转义为纯文本，不执行
2. **Given** 用户密码存储在数据库, **When** 查看数据库, **Then** 密码已经过bcrypt加密（不可逆）
3. **Given** 用户在登录页输入SQL注入语句, **When** 提交表单, **Then** 使用参数化查询防止注入攻击
4. **Given** API接口收到请求, **When** 请求未包含有效JWT Token, **Then** 返回401未授权错误
5. **Given** 用户尝试访问他人数据, **When** 请求发送到服务器, **Then** 验证用户权限并拒绝访问

---

### User Story 3 - 首页可视化仪表盘 (Priority: P2)

作为一名长期用户，我希望在首页看到我的成长可视化数据，包括练习热力图、总体进度、最近活动等，以便直观了解我的学习轨迹。

**Why this priority**: 可视化能增强用户粘性，但不是MVP必需功能。

**Independent Test**: 可以通过访问首页、查看热力图、总体统计、最近活动列表来完整测试。

**Acceptance Scenarios**:

1. **Given** 用户登录成功, **When** 进入首页, **Then** 显示包含以下区域的仪表盘：
   - 练习热力图（类似GitHub Contributions）
   - 所有职业角色的整体完成度统计
   - 最近7天的活动记录
   - 当前攻克中的技能卡片

2. **Given** 用户在过去365天内有练习记录, **When** 查看热力图, **Then** 每个日期格子的颜色深度反映当天的练习活跃度（日志数量）

3. **Given** 用户完成了50%的销售能力验收标准, **When** 查看统计卡片, **Then** 显示"销售能力: 50% (15/30)"

4. **Given** 用户点击热力图的某一天, **When** 弹出详情, **Then** 显示该天记录的所有练习日志

5. **Given** 用户在首页, **When** 点击"当前攻克中"的技能卡片, **Then** 跳转到该技能的详情页

---

### User Story 4 - UI优化：职业角色与技能分离 (Priority: P2)

作为一名用户，我希望职业角色页面不显示等级信息，只有进入具体技能后才看到5级进阶体系，以便让信息层级更清晰。

**Why this priority**: 优化信息架构，降低认知负担。

**Independent Test**: 可以通过点击职业角色、查看技能列表、进入技能详情来验证层级结构。

**Acceptance Scenarios**:

1. **Given** 用户在左侧导航栏选择"AI产品经理", **When** 右侧内容区显示, **Then** 只显示该角色下的技能列表（AI代理使用、代理工具），不显示等级信息

2. **Given** 用户点击"AI代理使用"技能, **When** 进入技能详情页, **Then** 显示该技能的5级进阶体系和验收标准

3. **Given** 用户在技能列表页, **When** 查看技能卡片, **Then** 显示：
   - 技能图标和名称
   - 整体完成度进度条
   - 当前等级徽章（如"Lv.2 优化者"）
   - 最后练习时间

4. **Given** 用户在职业角色页, **When** 查看整体进度, **Then** 显示该角色下所有技能的综合完成度

---

### User Story 5 - 数据导出与导入 (Priority: P3)

作为一名重视数据安全的用户，我希望能够手动导出我的所有数据为JSON文件，并在需要时导入，以便备份和迁移。

**Why this priority**: 增强用户数据掌控感，但不是核心功能。

**Independent Test**: 可以通过点击导出按钮、下载JSON文件、清空数据、导入文件来完整测试。

**Acceptance Scenarios**:

1. **Given** 用户在设置页, **When** 点击"导出数据", **Then** 下载包含所有技能数据和日志的JSON文件（文件名：`skill-tracker-backup-YYYYMMDD.json`）

2. **Given** 用户清空了本地数据, **When** 点击"导入数据"并选择之前的备份文件, **Then** 所有数据恢复到备份时的状态

3. **Given** 用户上传格式错误的文件, **When** 系统检测到格式不匹配, **Then** 显示错误提示："数据格式错误，请上传有效的备份文件"

---

### Edge Cases

- **网络断开**: 在离线状态下，数据仍保存在localStorage，联网后自动同步到服务器
- **JWT Token过期**: 自动弹出登录框，用户重新登录后继续操作
- **多设备冲突**: 后登录的设备覆盖云端数据（简单策略），后期可实现冲突合并
- **密码重置**: 通过邮箱验证码重置密码
- **热力图无数据**: 显示"还没有练习记录，开始你的第一次打卡吧！"
- **超长日志**: 限制单条日志最多5000字符

## Requirements *(mandatory)*

### Functional Requirements

**用户认证:**
- **FR-001**: 系统必须提供用户注册功能（用户名、邮箱、密码）
- **FR-002**: 系统必须提供用户登录功能（用户名/邮箱 + 密码）
- **FR-003**: 系统必须在用户登录后返回JWT Token
- **FR-004**: 系统必须验证JWT Token的有效性（每次API请求）
- **FR-005**: 系统必须提供退出登录功能（清除Token）
- **FR-006**: 系统必须限制密码强度（至少8位，包含大小写字母和数字）

**数据安全:**
- **FR-007**: 系统必须使用bcrypt加密存储用户密码
- **FR-008**: 系统必须对所有用户输入进行XSS过滤
- **FR-009**: 系统必须使用参数化查询防止SQL注入
- **FR-010**: 系统必须实现CORS跨域保护
- **FR-011**: 系统必须验证用户只能访问自己的数据

**首页仪表盘:**
- **FR-012**: 系统必须显示过去365天的练习热力图
- **FR-013**: 系统必须统计并显示所有职业角色的整体完成度
- **FR-014**: 系统必须显示最近7天的活动记录
- **FR-015**: 系统必须高亮显示当前正在攻克的技能
- **FR-016**: 系统必须支持点击热力图日期查看详情

**UI优化:**
- **FR-017**: 职业角色页面必须只显示技能列表，不显示等级信息
- **FR-018**: 技能卡片必须显示整体完成度和当前等级徽章
- **FR-019**: 只有进入技能详情页才显示5级进阶体系
- **FR-020**: 技能列表必须显示最后练习时间

**数据同步:**
- **FR-021**: 系统必须在用户操作时同时保存到localStorage和云端
- **FR-022**: 系统必须在登录后从云端同步最新数据
- **FR-023**: 系统必须提供数据导出功能（JSON格式）
- **FR-024**: 系统必须提供数据导入功能（验证格式）

### Key Entities

- **User (用户)**: 
  - id (自增主键)
  - username (用户名，唯一)
  - email (邮箱，唯一)
  - passwordHash (密码哈希)
  - createdAt (注册时间)
  - lastLoginAt (最后登录时间)

- **UserSkillData (用户技能数据)**:
  - id (自增主键)
  - userId (外键关联User)
  - skillData (JSON，存储完整的skills数组)
  - lastModified (最后修改时间)
  - version (数据版本号)

- **ActivityLog (活动日志)**:
  - id (自增主键)
  - userId (外键)
  - date (日期)
  - activityCount (当天活动次数)
  - details (JSON，存储具体活动)

- **HeatmapData (热力图数据)**:
  - 从 ActivityLog 计算生成
  - 格式：`{ date: '2025-11-25', count: 5, level: 3 }`

## Success Criteria *(mandatory)*

### Measurable Outcomes

**安全指标:**
- **SC-001**: 通过 OWASP Top 10 基础检测（XSS、SQL注入、认证漏洞）
- **SC-002**: 密码加密使用 bcrypt，salt rounds >= 10
- **SC-003**: JWT Token 有效期 24小时，刷新机制完善

**性能指标:**
- **SC-004**: 登录响应时间 < 500ms
- **SC-005**: 热力图渲染时间 < 1s（365天数据）
- **SC-006**: 数据同步延迟 < 2s

**用户体验指标:**
- **SC-007**: 90%的用户能在首次使用时3分钟内完成注册和登录
- **SC-008**: 热力图点击率 > 50%（用户会主动探索）
- **SC-009**: 数据导出成功率 100%

**业务指标:**
- **SC-010**: 用户注册后7天留存率 > 60%
- **SC-011**: 多设备登录用户占比 > 30%
